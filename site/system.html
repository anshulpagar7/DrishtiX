System · Architecture

Six stages, and a plan you can read

The contribution is the orchestration layer, not the models. Something decides what to run, says why, runs more than one thing when the task needs it, and combines the results. Adding a capability means registering a model — the routing logic never changes.

query ─▶ parse ─▶ validate ─▶ plan ─▶ execute ─▶ fuse ─▶ ground ─▶ Answer │ │ │ │ │ TaskSpec may REFUSE ExecPlan outputs veto-aware
01

Parse

Natural language becomes a structured TaskSpec: task type, modality, whether it needs an image pair. Rule parser by default; an LLM parser slots in behind the same interface and is cached to disk so a rate limit cannot break a demo.

02

Validate

Can the supplied images answer this question? Ask what changed with one image and it refuses, and says what to supply instead. Refusal is a first-class outcome, not an error path.

03

Plan

An ExecutionPlan is produced before anything runs and is attached to the answer. “Why did it do that” has a printed answer. Change queries plan more than one model, because localising a change and describing it are different jobs.

04

Execute

Models run in priority order. One failing is reported, not propagated — a single bad specialist cannot take the answer down.

05

Fuse

Outputs combine. Fusion never invents content; it selects, orders and joins text the models actually produced. Disagreement is surfaced and lowers confidence. A veto — say, two tiles of different places — suppresses every other output rather than sitting beside it.

06

Ground

Every answer carries the region, the model that produced it, and a confidence. Overlays are rendered server-side so there is one source of truth for where a box goes.

Registered models

Live from the running backend. Priority decides who wins a route: baselines sit at 0 and stay registered forever, so the system degrades instead of failing.

Integrating a trained model

The training module exposes exactly one function, run_vqa(image_path, query, adapter_dir), returning a fixed JSON shape. models/rsvqa.py is the only file that knows about it. Swap the backbone, retrain, change LoRA rank — nothing else in this repo moves.
